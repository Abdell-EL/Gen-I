# Known Limitations and Roadmap

Status labels:

- **IMPLEMENTED**: present in the repository/application.
- **VALIDATED**: covered by repository checks or documented runbooks.
- **REQUIRES IT / NOT YET VALIDATED**: needs production approval, infrastructure implementation, or further validation.

| Limitation | Status | Impact | Current mitigation | Owner/team | Recommended next action | Priority |
| --- | --- | --- | --- | --- | --- | --- |
| Microsoft Entra ID is not implemented | REQUIRES IT / NOT YET VALIDATED | No SSO, conditional access, tenant identity lifecycle, or centralized MFA. | Local email/password auth with roles `admin` and `agent`. | Security team and IT/deployment team | Approve identity architecture and implement Entra/OIDC integration. | High |
| Outlook/Graph email delivery requires tenant approval | REQUIRES IT / NOT YET VALIDATED | Invitations and password resets cannot send production email. | `noop` default provider and `capture` local/test provider only. | Security team and IT/deployment team | Obtain tenant approval and implement a production email/outbox provider. | High |
| Current email provider modes are not production delivery | IMPLEMENTED | Account lifecycle needs admin/operator handling unless real provider is added. | Delivery status is tracked without storing raw URLs by default. | Application developer and IT/deployment team | Add approved provider and operational monitoring for delivery failures. | High |
| Local React Router advisory exception expires on 2026-08-17 | VALIDATED | CI will fail on 2026-08-18 if the exception remains. | Scoped exception for `GHSA-qwww-vcr4-c8h2`; app is client-rendered Vite SPA without RSC APIs. | Application developer/security team | Upgrade to a compatible patched React Router release and remove exception. | High |
| No automatic database schema rollback | IMPLEMENTED | Application rollback does not undo Alembic migrations; incompatible schema changes increase recovery risk. | Forward-only migration policy and pre-deploy PostgreSQL backup. | Application developer and IT/deployment team | Require backward-compatible migrations and rehearse restore decisions. | High |
| No version restore endpoint | REQUIRES IT / NOT YET VALIDATED | Admins can list and upload versions, but cannot restore a previous document version through an API endpoint. | Previous DOCX/version data remains stored when available. | Application developer/business knowledge owner | Add reviewed restore/re-publish endpoint with audit and Milvus handling. | Medium |
| Monitoring maturity | REQUIRES IT / NOT YET VALIDATED | No production alerting stack is configured by this repository. | Health endpoint and operational commands are documented. | IT/deployment team | Add uptime, container, disk, PostgreSQL, Redis, Milvus, Ollama, Nginx, and log alerting. | High |
| Load-testing status | REQUIRES IT / NOT YET VALIDATED | Capacity for 50 or 500 users is not proven. | Opt-in benchmark runbooks exist; no destructive load tooling is run by CI. | IT/deployment team/application developer | Run controlled load tests on production-like infrastructure with accepted success criteria. | High |
| High availability is not implemented | REQUIRES IT / NOT YET VALIDATED | Single VM is a single point of failure. | Single-VM deployment is explicit and operationally simpler. | IT/deployment team/management approver | Define HA target before wider rollout. | Medium |
| Single-VM deployment assumptions | IMPLEMENTED | VM resource exhaustion or host outage affects all services. | Persistent volumes and runbooks are documented. | IT/deployment team | Confirm VM sizing, backups, monitoring, and maintenance windows. | High |
| No automatic registry publishing | IMPLEMENTED | API image is built on the VM; deploy depends on VM build tooling and network/package access. | Deployment script builds exact Git SHA on VM. | IT/deployment team/application developer | Add approved image registry if supply-chain or deployment speed requires it. | Medium |
| No zero-downtime multi-instance deployment | IMPLEMENTED | API replacement can cause brief downtime; migrations must be backward-compatible. | Build happens before `api` replacement; dependencies are not restarted by deploy. | IT/deployment team/application developer | Add reverse proxy/service strategy before strict zero-downtime SLA. | Medium |
| Milvus resource limitations | REQUIRES IT / NOT YET VALIDATED | Vector search depends on local Milvus, etcd, and MinIO resources; large corpus growth can degrade performance. | Health compares vector count to PostgreSQL chunks. | IT/deployment team | Monitor memory/disk/vector count and define backup/regeneration strategy. | High |
| Ollama resource limitations | REQUIRES IT / NOT YET VALIDATED | Generation latency and reliability depend on VM CPU/GPU/RAM and local model availability. | Baseline model is `llama3.2:3b`; runbook documents benchmark controls. | IT/deployment team/application developer | Benchmark on target hardware and approve model/runtime settings. | High |
| Current 3B model choice and quality rationale | IMPLEMENTED | `llama3.2:3b` favors local deployment and reasonable answer quality over larger-model quality. | `llama3.2:1b` fast profile exists but is disabled by default; benchmark doc requires human review. | Business knowledge owner/application developer | Run business-owner answer quality review before broad rollout. | Medium |
| Legacy Alembic adoption | IMPLEMENTED | First migrations expect an existing legacy schema and do not create every table from blank PostgreSQL. | CI bootstraps a minimal disposable legacy schema before Alembic upgrade. | Application developer | Add a full baseline migration or documented production schema bootstrap if greenfield deploy is required. | Medium |
| Missing database uniqueness constraints for some domain entities | REQUIRES IT / NOT YET VALIDATED | Some duplicate prevention is application-level, for example KB code detection through chunk metadata rather than a database unique constraint. | `users.email`, `roles.name`, `departments.code`, token hashes, and `(document_id, version_number)` have uniqueness; ingestion checks checksum and KB code before insert. | Application developer | Add database constraints/indexes for stable domain identifiers after data cleanup review. | Medium |
| Keyword index refresh limitation after DOCX upload | IMPLEMENTED | Ingestion config notes semantic search is available after Milvus insert, while file-backed keyword index is not refreshed in the MVP. | Semantic search and chat use indexed vectors; admin can verify ingestion job output. | Application developer/business knowledge owner | Move keyword search fully to PostgreSQL or refresh index after ingestion. | Medium |
| Real-browser lifecycle rehearsal | REQUIRES IT / NOT YET VALIDATED | Unit/source tests do not prove browser history, focus, autocomplete, or mobile interaction behavior. | Frontend tests cover lifecycle logic; docs call out rehearsal need. | Application developer/platform administrator | Run a disposable real-browser UAT pass before pilot. | Low |
| MFA, refresh tokens, durable session/device management | REQUIRES IT / NOT YET VALIDATED | Sessions are short-lived JWT access tokens stored in browser session storage; no central device/session controls. | Token version invalidates prior JWTs after credential replacement. | Security team/application developer | Decide whether Entra ID replaces or augments these controls. | Medium |
| Redis/IP rate limiting | REQUIRES IT / NOT YET VALIDATED | Auth and reset endpoints do not have production-grade IP throttling beyond database-backed resend cooldowns. | Invitation and reset resend cooldowns are persistence-backed per account. | Security team/application developer | Add gateway or app-level rate limiting. | High |
| Third-party GitHub Action SHA pinning incomplete | REQUIRES IT / NOT YET VALIDATED | Some actions use tags; supply-chain hardening is incomplete. | Security workflow documents this as a remaining item; Trivy action is pinned to a commit SHA. | Security team/application developer | Pin all third-party actions after review. | Medium |
